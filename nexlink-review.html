مراجعة منصة NexLink Control Center

تحليل تقني للمنصة المنشورة على z.ai، مع الأخطاء الحرجة وخطة تطوير بثلاث مراحل لتصبح منصة اتصال طوارئ يمكن الاعتماد عليها فعلاً.

المصدر: e1fja9dh8df0-d.space-z.aiتاريخ الفحص: 18 نوفمبر 2026الطريقة: تصفّح التبويبات العشرة وقراءة الواجهات البرمجية (قراءة فقط، دون إرسال أي بيانات)

الخلاصة

المنصة لوحة تحكم مؤسسية جيدة الشكل ومتعددة اللغات، مبنية بـ Next.js، لإدارة شبكة أجهزة طوارئ. فكرتها قوية، لكنها اليوم عرض توضيحي ببيانات تجريبية وليست جاهزة للتشغيل الميداني. قبل إضافة أي ميزة جديدة يجب إصلاح ثلاث مشكلات:

  • واجهة الأجهزة مفتوحة للعموم وتكشف أسماء الأشخاص وجهات عملهم وإحداثيات GPS دقيقة.
  • أي شخص على الإنترنت يستطيع إرسال نداء استغاثة أو إخلاء لكل الأجهزة، لأن واجهة الإذاعات لا تطلب تسجيل دخول ولا توقيعاً.
  • أزرار تحميل التطبيق لا تحتوي روابط لملفات فعلية.

نقاط القوة

واجهة عربية متقنة باتجاه RTL صحيح، وخط IBM Plex Arabic، و11 لغة.
نموذج بيانات مدروس: مفاتيح Ed25519 وX25519 لكل جهاز، وبصمات، وعدد القفزات، ونوع النقل.
مقاييس شبكة مفيدة مثل الانقسامات والجسور وتوزيع جودة الروابط، وهي ما يحتاجه مشغّل ميداني.
رؤية معمارية واضحة للطبقات (اكتشاف، صوت وفيديو، تخزين، سجلات) يمكن البناء عليها.

المشكلات مرتبة حسب الخطورة

حرجة

كشف بيانات شخصية ومواقع دقيقة دون تسجيل دخول

الطلب GET /api/devices يُرجع لأي زائر اسم كل شخص وجهة عمله (مثل «ريم • Mecca Logistics») وإحداثياته بدقة 14 خانة عشرية، أي بدقة أقل من سنتيمتر. هذا يناقض وعد «بدون بيانات شخصية»، وقد يعرّض فرق الإنقاذ للخطر في مناطق النزاع.

الإصلاح: قفل كل واجهات /api خلف تسجيل دخول بأدوار (مشغّل، مشرف، قراءة فقط)، وإرجاع موقع تقريبي فقط (Geohash من 6 خانات ≈ 1 كم)، وحذف الاسم والقسم من الردّ العام.

حرجة

أي شخص يستطيع إطلاق نداء استغاثة أو إخلاء لكل الأجهزة

الواجهة الأمامية ترسل POST /api/broadcasts بلا رمز دخول وبلا توقيع، بالحقل targetDeviceIds: "ALL". وجود إذاعات بعنوان «اختبار المنصة بعد الإصلاح» يؤكد أن الكتابة مفتوحة. كذلك يُنشئ POST /api/contracts مفتاح الناشر عشوائياً داخل المتصفح، فلا يثبت التوقيع من نشر العقد. إنذار إخلاء مزيّف واحد قد يسبب ذعراً حقيقياً.

الإصلاح: يجب أن يحمل كل أمر بث توقيع Ed25519 من مفتاح مشغّل مسجّل، يتحقق منه الخادم وتتحقق منه كل الأجهزة أيضاً. يُضاف حدّ للمعدّل، ويُشترط توقيعان (2 من 3) لنداءات الإخلاء العامة.

عالية

التحميل لا يعمل

صفحة «تحميل التطبيق» تعرض أزراراً وأحجام ملفات وبصمات SHA-256، لكن الصفحة لا تحتوي أي رابط فعلي، ولا رابط للكود المصدري رغم عبارة «مفتوح المصدر بالكامل».

الإصلاح: نشر ملف APK فعلي على GitHub Releases مع البصمة، ونشر الـ PWA بملف manifest وService Worker، ووضع رابط المستودع.

عالية

البيانات ثابتة وأرقام متناقضة

آخر لقطة لصحة الشبكة مؤرخة 11 نوفمبر، والإذاعات الحديثة عدد تأكيداتها صفر، و4 من 16 جهازاً غير متصلة منذ أيام. في الصفحة نفسها يظهر مؤشر الشبكة 83 وبجانبه «الصحة العامة 78»، وشارة «ممتاز» بينما لوحة المعلومات تقول «جيد» ونسبة الروابط الممتازة 0٪. المشغّل في الميدان سيفقد الثقة بالأرقام.

الإصلاح: مصدر واحد لحساب المؤشر، وتحديث حيّ عبر Server-Sent Events، ووقت آخر تحديث بجانب كل رقم مع تحذير عندما تكون البيانات قديمة.

عالية

لوحة التحكم نفسها تحتاج الإنترنت

المنصة مستضافة على الإنترنت، بينما الكارثة التي صُممت لها تقطع الإنترنت. ستنقطع غرفة العمليات عن الأجهزة في اللحظة التي تحتاجها فيها.

الإصلاح: نسخة «غرفة عمليات ميدانية» تعمل على حاسوب محمول أو Raspberry Pi متصل بالشبكة المتداخلة كأي جهاز آخر، وتتزامن مع الخادم السحابي عند عودة الاتصال.

متوسطة

الإجماع والتوكنز قد يعطّلان الطوارئ

إجماع pBFT مع 7 مصادِقين يحتاج 5 موافقات. عند انقسام الشبكة، وهو أمر طبيعي في الكوارث، تتوقف الكتل. ومرساة Polygon تحتاج إنترنت. أما مكافآت RELAY فتشجّع على تمرير رسائل وهمية لكسب التوكنز.

الإصلاح: نداء الاستغاثة لا ينتظر أي إجماع ويُمرَّر فوراً. السجل يكون محلياً لكل جهاز (Hypercore) ويُدمج لاحقاً. المكافأة تُحسب على التسليمات المؤكدة بإيصال موقّع من المستلم، وليس على عدد الرسائل الممرّرة.

متوسطة

ادعاءات تسويقية يصعب إثباتها

جدول «الأفضل عالمياً 16/16» يقارن مع WhatsApp وMessenger ويضع علامة الإنجاز على ميزات غير موجودة في النسخة الحالية. المنظمات الإنسانية تقيّم بالأدلة، وهذا الجدول قد يضر بالمصداقية.

الإصلاح: مقارنة مع منافسين حقيقيين في المجال نفسه (Briar وBridgefy وMeshtastic وFireChat)، وإظهار حالة كل ميزة: متاحة، أو تجريبية، أو مخطط لها.

خطة التطوير والميزات الجديدة

المرحلة 1 · أسبوعان · الأمان والثقة

جعل المنصة آمنة للاستخدام الحقيقي

  • تسجيل دخول المشغّلين بأدوار وصلاحيات، ومفتاح Ed25519 لكل مشغّل يوقّع به أوامر البث.
  • تقليل البيانات: موقع تقريبي افتراضياً، وموقع دقيق فقط مع نداء استغاثة وبموافقة صاحبه.
  • سجل تدقيق لكل أمر بث: من أرسله، ومتى، وبأي توقيع.
  • تحميل فعلي لملف APK والـ PWA مع البصمات ورابط المستودع.
  • بيانات حيّة عبر SSE، ومؤشر صحة موحّد، وتنبيه عند قِدم البيانات.
المرحلة 2 · 6 أسابيع · ميزات ميدانية

ما تحتاجه فرق الإنقاذ فعلاً

  • طابور فرز الاستغاثات: كل نداء له خطورة وفريق مكلّف وحالة (استُلم، كُلّف فريق، في الطريق، تم الإنقاذ)، وتصل الحالة لصاحب النداء عبر الشبكة.
  • «أنا بخير»: زر واحد يرسل تأكيد سلامة للعائلة ومركز العمليات، مع بحث عن المفقودين بالبصمة.
  • خرائط بلا إنترنت بملفات PMTiles محمّلة مسبقاً، مع طبقات للملاجئ والمستشفيات ونقاط المياه.
  • تتبع الإيصالات: كل جهاز يرسل إيصالاً موقّعاً عند الاستلام، فيعرف المشغّل من وصله الإنذار ومن لم يصله.
  • أولويات في التخزين والتمرير: الاستغاثة أولاً، ثم الرسائل النصية، ثم الصور، مع حد أقصى لعمر الرسالة.
  • جسر LoRa / Meshtastic لمدى يصل إلى عدة كيلومترات بأجهزة رخيصة، يربط الأحياء المنفصلة.
  • بوابة احتياطية: أي جهاز يجد إنترنت أو قمراً صناعياً أو رسائل SMS يرفع الاستغاثات المتراكمة تلقائياً.
  • توفير البطارية: الجهاز الذي بطاريته أقل من 20٪ يتوقف عن التمرير ويحتفظ بقدرته على الإرسال والاستقبال.
  • وضع التدريب: نداءات تجريبية معلّمة بوضوح لا تختلط بالحقيقية.

ميزات تميّز المنصة عن المنافسين

  • فرز ذكي للاستغاثات: نموذج صغير يعمل على الهاتف بلا إنترنت يقرأ نص النداء ويقدّر الخطورة (نزيف، أطفال، محاصرون).
  • ترجمة فورية بلا إنترنت بين اللغات الإحدى عشرة، مفيدة في مخيمات اللاجئين والحج.
  • تخطيط التغطية: تحليل الانقسامات واقتراح أماكن وضع أجهزة تقوية لربط العناقيد المعزولة.
  • كشف الانتحال: رصد أجهزة تبث بكثافة غير طبيعية أو بمفاتيح غير مسجلة، وعزلها تلقائياً.
  • رسائل صوتية مضغوطة بترميز Codec2 (أقل من 2 كيلوبت/ثانية) لمن لا يستطيع الكتابة.

مثال على إصلاح البث المفتوح

هذا شكل مسار البث بعد الإصلاح في Next.js: لا يُقبل أي أمر إلا من مشغّل مسجّل وبتوقيع صالح ووقت حديث.

// app/api/broadcasts/route.ts
import { verify } from "@noble/ed25519";
import { prisma } from "@/lib/db";
import { getOperator } from "@/lib/auth";

export async function POST(req: Request) {
  const op = await getOperator(req);               // session + role check
  if (!op || !op.roles.includes("broadcaster"))
    return Response.json({ error: "غير مصرّح" }, { status: 401 });

  const { payload, signature } = await req.json(); // payload = JSON string
  const msg = JSON.parse(payload);
  const fresh = Math.abs(Date.now() - msg.ts) < 60_000;
  const ok = fresh && await verify(signature, new TextEncoder().encode(payload), op.ed25519PublicKey);
  if (!ok) return Response.json({ error: "توقيع غير صالح أو منتهي" }, { status: 403 });

  if (msg.type === "EVACUATION" && !(await hasCoSigner(msg)))
    return Response.json({ error: "الإخلاء يحتاج توقيع مشرف ثانٍ" }, { status: 409 });

  const b = await prisma.broadcast.create({ data: { ...msg, triggeredById: op.id, signature } });
  await prisma.auditLog.create({ data: { actor: op.id, action: "BROADCAST", ref: b.id } });
  return Response.json(b, { status: 201 });
}
